**Verdict:** A (Plotly + Jinja2 + Chromium) is a reasonable choice for the simplest working version. The decision record is fair to B. Nothing in the reference inventory needs anything A can't do, and the custom 4:3 page size is ordinary in Chromium. The one measured difference is the one that matters for the no-clipping rule. In B, the overfilled 10 mm box rendered silently: the only public anchor reported the allocated box, and nothing flagged the overflow. In A it showed up as 38 px visible height against 840 px of content, a direct rejection signal. The experiment shows A is feasible, not that it is correct; the traps below are where a naive build would still clip or misrender.

## Measurement traps (overflow contract)

1. **The overflow probe measured on screen, not on the printed page.** It used a 1047×718 viewport and then `page.pdf(format="A4")`, so the layout it measured differs from the one it printed. The overfilled box also spilled onto a second PDF page without any error. Instead:
   - Set the viewport to the page's content size in CSS px (mm × 96 / 25.4) and emulate print media before measuring.
   - Use `@page { size: W H; margin: … }` with `prefer_css_page_size=True`, and don't pass `format`.
   - The 1600×1200 pt reference becomes roughly 564.4×423.3 mm.
   - Keep the PDF page count as a backstop: a dashboard page must produce exactly one PDF page.
2. **Flex items can hide overflow.** In a flex layout, children have `min-height`/`min-width: auto`, so an overfull card may stretch instead of overflowing. The overflow then shows up on an ancestor, or only as a misaligned row. Set `min-width: 0; min-height: 0` on every fixed or weighted container and measure all of them, not just the leaves.
3. **Check width too, with a small tolerance.** `clientHeight`/`scrollHeight` are rounded integers. Compare both height and width (long unbreakable tokens overflow sideways). Allow about 1 px, or use `getBoundingClientRect()` for fractional values. Keep `overflow: visible`; `hidden`/`clip` would make the overflow invisible in the output.
4. **`scrollHeight` can't see inside Plotly charts.** Chart text is SVG, so:
   - Plotly can silently skip tick labels on a crowded category axis. Assert the number of rendered tick labels equals the number of categories.
   - Automargin can shrink the plot area to nothing. Assert the plot area stays above a minimum size, and that the text bounding boxes (`getBBox`) sit inside the SVG.

## Plotly traps (all hit the reference report)

5. **Horizontal bar order is reversed by default.** Plotly draws the first category at the bottom. The funnel and attempts charts need `yaxis.autorange="reversed"` (or explicit category order) to keep the source order.
6. **A single date gets a time axis.** One bar on 2026-11-04 will produce hour ticks. Use `type="category"` for the calendar's x-axis.
7. **Labels are partly interpreted as HTML.** Plotly renders `<b>`, `<br>`, `<a>` and decodes entities, so hostile or literal-markup labels won't appear literally. Escape `&` and `<` before passing labels in. Separately, make sure the embedded JSON can't contain a literal `</script>` (escape `</`); Jinja2 autoescape doesn't cover script contexts.
8. **Plotly measures text before fonts load.** If the font isn't ready, margins are computed with fallback metrics. The experiment named "DejaVu Sans", which isn't guaranteed on macOS. Bundle the font as `@font-face` (data URI or a controlled route), await `document.fonts.ready`, then call `Plotly.newPlot`. Wait for its returned promise, not just for `.main-svg` to exist.
9. **Size and determinism.** Inline plotly.js once per document, not once per chart (about 3.5 MB each). Pass `include_mathjax=False` and set `staticPlot`. Div ids are random, so tests must not hash the HTML.

## Browser and lifecycle traps

10. **Offline enforcement.** Use `page.route("**/*")` to abort everything except your own data/bundled resources, and record any attempted fetch as a test failure.
11. **Notebooks break the sync API.** Playwright's sync API raises inside a running asyncio loop, which is the default in Jupyter. Either run rendering in a worker thread or use the async API internally from the start.
12. **Missing Chromium and cleanup.** Pin the Playwright version, since the Chromium build is tied to it. When Chromium is missing, raise a clear error naming the install command; never auto-download. Close the browser in `finally` on every error path.
13. **HTML output can be JS-free.** After render and checks, serialize the DOM with the finished SVGs and strip the scripts. The HTML then needs no JavaScript and matches what was measured, which removes the "HTML preview needs JS" item from the candidate table.

## What not to over-build now

- Linux verification, a Windows claim, and table/flow pagination (the 120-row probe is enough evidence for Slice 2). The reference report has only a 2-row table.
- Oversized-row rejection is untested; leave it for Slice 2 rather than claiming it.
- No backend abstraction.

**Minimum gates before calling v0.1 working:**
- The reference report renders as one page at the custom size.
- Every expected label and number is extractable from the PDF, with no raster images.
- Bar order matches the source.
- An overfilled card raises an error and no output file is written.
- A hostile/Cyrillic label renders literally.
- The bundled font is embedded in the PDF.
- Zero external fetches.
